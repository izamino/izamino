# کارتابل اداری مجتمع مسجدمحور شباب اهل‌الجنه

سامانه تحت وب، فارسی، راست‌چین و واکنش‌گرا برای مدیریت امور اداری ۱۹ مدیریت مستقل زیر نظر امام جماعت، به‌همراه بخش عمومی «کتابخانه و رزرو کتاب» برای مردم.

## ساختار سازمانی

امام جماعت در رأس ساختار است (بدون جایگاه «مدیریت کل مجتمع») و ۱۹ مدیریت مستقل زیر نظر ایشان:
داخلی مجتمع · امور فرهنگی و هنری · روابط عمومی · رسانه · پایگاه بسیج خادم‌الشهدا حاج احمد یلالی · دبستان · متوسطه اول · متوسطه دوم · درمانگاه · داروخانه · کتابخانه · خیریه و گروه جهادی · خانه‌بازی کودک و مهدکودک · امور اداری · امور مالی · فناوری اطلاعات · طرح و برنامه (عمران و توسعه زیرمجموعه آن) · مراسمات و مناسبت‌ها، فاتحه، جشن و اعیاد · رستوران.

هر مدیریت سه جایگاه و سه پنل مستقل دارد: مدیر، مسئول دفتر، منشی؛ یعنی ۵۷ حساب سازمانی به‌علاوه حساب امام جماعت.

### حساب‌ها و پنل‌ها بر پایه جایگاه

- نام پنل به نام جایگاه است (مثلاً «پنل مسئول دفتر مدیریت کتابخانه»)؛ نام فرد فقط به‌عنوان «متصدی فعلی» نمایش داده می‌شود.
- نام کاربری ثابت و بر پایه مدیریت و جایگاه است: `imam`، `library.manager`، `library.office`، `library.secretary`، `restaurant.manager` و …؛ با تغییر افراد عوض نمی‌شود.
- **ویرایش مشخصات متصدی** (نام، نام خانوادگی، تماس) جدا از **تغییر متصدی و تحویل مسئولیت** است. در تحویل: پنل، نام کاربری، مکاتبات و سوابق می‌ماند؛ کارهای در انتظار به متصدی جدید می‌رسد؛ رمز تازه و تصادفی ساخته و نشست‌های متصدی قبلی بسته می‌شود؛ تاریخ تحویل و نام متصدی قبلی در سابقه جایگاه می‌ماند و اقدامات گذشته با نام انجام‌دهنده همان زمان باقی است.

### نظارت مدیر بر دفتر خودش

در کارتابل هر مدیریت، مدیر دو بخش دارد:
- **نظارت بر دفتر:** وظایف ارجاع‌شده، انجام‌شده، باقی‌مانده و معوق مسئول دفتر و منشی، اقدامات اخیر، ارجاع کار با مهلت و گزارش عملکرد ۷، ۳۰ یا ۹۰ روزه.
- **مدیریت دسترسی‌های دفتر:** محدودکردن یا فعال‌سازی دوباره دسترسی‌های مسئول دفتر و منشی (مشاهده و ثبت مکاتبات، ارجاع نامه، وظایف، درخواست‌ها، جلسات و رزرو، گزارش‌ها، پیوست‌ها). مدیر فقط تا سقف تعیین‌شده مدیریت عالی و فقط برای دفتر خودش اختیار دارد؛ هر تغییر با نام و زمان ثبت و روی سرور هنگام مشاهده و اجرا بررسی می‌شود.

مدیر هیچ بخشی، صرفاً به دلیل مدیر بودن، به کارکنان یا اطلاعات بخش‌های دیگر دسترسی ندارد.

## کتابخانه و رزرو کتاب (بخش عمومی)

نشانی عمومی: `/library` (یا `#library`). مردم بدون ورود به کارتابل اداری فهرست کتاب‌ها و موجودی را می‌بینند، عضو می‌شوند، درخواست رزرو یا امانت ثبت می‌کنند و وضعیت، پاسخ کتابدار، موعد بازگشت و سابقه خود را پیگیری می‌کنند. حساب اعضا با کوکی و نشست جداگانه کاملاً از حساب کارکنان جداست و به هیچ اطلاعات اداری دسترسی ندارد.

فرایند: انتخاب کتاب ← ورود یا عضویت ← ثبت درخواست ← بررسی کتابدار ← تأیید و اختصاص یک نسخه آزاد و اعلام مهلت مراجعه ← ثبت تحویل و موعد بازگشت ← ثبت بازگشت و آزادشدن نسخه. موجودی بر اساس نسخه‌های واقعی کنترل می‌شود و یک نسخه هم‌زمان به دو نفر اختصاص نمی‌یابد.

مدیر کتابخانه دو بخش جدا دارد: **خدمات عمومی کتابخانه** (کتاب‌ها و نسخه‌ها، درخواست‌ها، امانت‌ها و تأخیرها، اعضا) و **کارتابل اداری مدیریت کتابخانه** (نامه، ارجاعات، وظایف، درخواست‌های داخلی، نظارت بر دفتر).

دو نسخه از یک کد ساخته می‌شود:

| نسخه | کاربرد | داده |
|---|---|---|
| **نسخه سروری (عملیاتی)** — `server/` | بهره‌برداری واقعی چندکاربره | پایگاه داده SQLite روی سرور؛ مرورگر هیچ داده‌ای نگه نمی‌دارد |
| نسخه نمایشی — `dist/index.html` و پیش‌نمایش claude.ai | آشنایی و آزمایش | داده نمونه در مرورگر؛ برای اطلاعات واقعی مناسب نیست |

## راه‌اندازی نسخه سروری

نیازمندی: **Node.js 22.5 یا بالاتر** (بدون هیچ بسته اضافه؛ SQLite و scrypt داخلی Node استفاده می‌شوند).

```bash
cd kartabl
node build.mjs                                   # ساخت فایل‌های رابط کاربری
cd server
npm run init                                     # پایگاه داده خالی: ۵۸ جایگاه، بدون حساب و بدون داده نمونه
node --disable-warning=ExperimentalWarning server.js provision
npm start                                        # http://127.0.0.1:8080
```

`provision` برای هر ۵۸ جایگاه یک حساب با نام کاربری سازمانی و **رمز اولیه مستقل و تصادفی** می‌سازد و فهرست را فقط در فایل خصوصی `DATA_DIR/credentials-….csv` (دسترسی فقط مالک فایل) می‌نویسد؛ رمزها در خروجی فرمان، صفحه‌های سایت یا کد مرورگر نیستند. تغییر رمز در اولین ورود الزامی است. پس از تحویل رمزها، این فایل را حذف کنید.

برای ثبت متصدی هر جایگاه: از پنل «تغییر متصدی و تحویل مسئولیت» یا در خط فرمان `server.js set-holder --pos P11-o --first "نام" --last "نام خانوادگی" --phone 0912…`.

### استقرار روی سرور

- فایل‌های نمونه در `server/deploy/`: سرویس systemd و پیکربندی nginx با HTTPS.
- پشت HTTPS حتماً `COOKIE_SECURE=1` و پشت nginx `TRUST_PROXY=1` تنظیم شود.
- متغیرها: `PORT`، `HOST`، `DATA_DIR` (محل پایگاه داده، فایل‌ها و نسخه‌های پشتیبان).

### فرمان‌های سرور

| فرمان | کار |
|---|---|
| `server.js init` | ساخت پایگاه داده خالی عملیاتی |
| `server.js init --demo` | پایگاه آزمایشی با داده نمونه (رمز همه ۱۲۳۴) — **فقط برای آزمایش** |
| `server.js provision` | ساخت حساب همه جایگاه‌های بدون حساب با رمز اولیه تصادفی در فایل خصوصی |
| `server.js set-holder --pos <جایگاه> --first <نام> --last <نام خانوادگی>` | ثبت متصدی و رمز موقت |
| `server.js reset-password --username <نام>` | رمز موقت جدید (مثلاً اگر امام جماعت رمز را فراموش کند) |
| `server.js backup` | نسخه پشتیبان فوری |
| `server.js verify-audit` | بررسی سلامت زنجیره رویدادها |

### پیامک

در «پنل مدیریت › پیامک» سرویس‌دهنده (کاوه‌نگار یا درگاه اختصاصی)، کلید و شماره خط را وارد کنید و «ارسال پیامک آزمایشی» را بزنید. وضعیت هر پیامک واقعی است: در صف ارسال، ارسال‌شده، تحویل‌شده، تحویل نشد، ناموفق. کلید فقط روی سرور می‌ماند و متن پیامک هیچ جزئیات محرمانه‌ای ندارد.

### آزمون‌ها

```bash
node test/server-test.mjs   # ۱۳۰ آزمون امنیت و درستی سرور
node test/ui-test.mjs       # پیمایش کامل رابط روی سرور، تزریق HTML، فوکوس، گوشی و آیپد (نیازمند Playwright)
```

## ساختار کد

| فایل | محتوا |
|---|---|
| `src/core.js` | تاریخ شمسی، ساختار سازمانی، سالن‌ها و انواع برنامه، مجوزها، رویدادها |
| `src/domain.js` | قواعد و گردش کار و اعتبارسنجی‌های مشترک |
| `src/domain-admin.js` | حساب جایگاه‌ها، تحویل مسئولیت، رمز، دسترسی‌ها، عضویت، تأیید مدیریتی، تنظیمات |
| `src/domain-library.js` | کتابخانه عمومی: کتاب، نسخه، عضو، رزرو و امانت |
| `src/ops.js` | **تنها مسیر تغییر داده**: فهرست عملیات مجاز با بررسی مجوز |
| `src/ui.js`، `src/pages*.js`، `src/admin.js` | رابط کاربری |
| `src/office.js` | پنل‌ها و متصدیان، نظارت بر دفتر، دسترسی‌های دفتر، حساب متصدی |
| `src/library-ui.js` | سایت عمومی کتابخانه و بخش خدمات عمومی کتابدار |
| `src/remote.js` | اتصال رابط به سرور |
| `src/sync.js` | همگام‌سازی پیش‌نمایش claude.ai (فقط نسخه نمایشی) |
| `server/server.js` | سرور: ورود، نشست، تراکنش، فایل، پیامک، پشتیبان |
| `server/view.js` | تعیین داده مجاز هر کاربر |
| `server/vendor/qrcode-generator.js` | تولید QR (کتابخانه MIT، Kazuhiko Arase) |
