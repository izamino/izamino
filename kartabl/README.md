# کارتابل اداری مجتمع مسجدمحور شباب اهل‌الجنه

سامانه تحت وب، فارسی، راست‌چین و واکنش‌گرا برای مدیریت امور اداری ۱۷ مدیریت مستقل زیر نظر امام جماعت.

## اجرا

```bash
node build.mjs          # ساخت dist/index.html (نسخه مستقل) و dist/kartabl.html (پیش‌نمایش)
open dist/index.html    # یا روی هر وب‌سرور ایستا
```

حساب‌های نمونه (رمز همه `1234`): `imam` · مدیران `m1`…`m17` · مسئولان دفتر `o1`…`o17` · منشی‌ها `s1`…`s17` · کارشناسان مثل `k1-1`.

## پنل مدیریت سامانه (مدیر فناوری اطلاعات — `m16`)

| بخش | امکانات |
|---|---|
| نمای کلی | وضعیت کاربران، ورودهای امروز، حساب‌های قفل، نشست‌ها، سلامت زنجیره رویدادها، اقدامات سریع |
| کاربران | افزودن، ویرایش، حذف، فعال/غیرفعال‌سازی، تعیین رمز (با پیشنهاد رمز تصادفی و الزام تغییر)، بازکردن قفل، خروج اجباری، تغییر متصدی و افزودن/حذف جایگاه |
| درخواست عضویت | تأیید (با ایجاد جایگاه جدید یا انتخاب جایگاه خالی) یا رد درخواست‌هایی که از صفحه ورود ثبت می‌شود |
| سطوح دسترسی | ماتریس ۲۱ مجوز × ۵ نقش (پیش‌فرض/مجاز/ممنوع) و استثنای هر جایگاه (پیش‌فرض/اعطا/سلب) |
| تأیید و رد | همه موارد معلق سامانه (درخواست، دستور، پرداخت، رزرو، مرخصی، گردش کالا، وظیفه) با تأیید یا رد مدیریتی که با نام مدیر در سابقه ثبت می‌شود |
| ورودها و نشست‌ها | تاریخچه ورود موفق/ناموفق با فیلتر، نشست‌های فعال و پایان دادن به آن‌ها |
| رویدادهای سیستمی | همه اقدامات با فیلتر کاربر، مدیریت، موجودیت و تاریخ؛ غیرقابل حذف |
| ظاهر و محتوا | نام مجموعه، متن‌های صفحه ورود، اطلاعیه عمومی، ۵ رنگ‌بندی، اندازه متن، شهر و مختصات اوقات شرعی |
| ساختار سازمانی | نام مدیریت‌ها، خدمات هر مدیریت، فضاهای رزرو، فهرست‌های پایه |
| امنیت | حداقل طول رمز، تعداد تلاش تا قفل، مدت قفل، خروج خودکار، حالت به‌روزرسانی، خروج همه، الزام تغییر رمز همه |
| ویرایش داده‌ها | مشاهده، ویرایش و حذف مستقیم هر رکورد در ۲۴ مجموعه داده (رمزها و رویدادها مستثنا) |
| پیامک و پشتیبان‌گیری | تنظیمات و صف پیامک، تهیه و بازیابی نسخه پشتیبان |

رمزها هش‌شده ذخیره می‌شوند؛ هیچ‌کس رمز فعلی کاربران را نمی‌بیند و مدیر سامانه رمز جدید تعیین می‌کند.

## ساختار کد

| فایل | محتوا |
|---|---|
| `src/core.js` | تاریخ شمسی، ساختار سازمانی (۵۲ جایگاه اصلی)، دسترسی‌ها، زنجیره ثبت رویداد، اعلان و پیامک |
| `src/domain.js` | قواعد و گردش کار: دبیرخانه، دستورات، وظایف، درخواست‌ها، رزرو، جلسات، اموال، مالی، منابع انسانی، کاربران |
| `src/seed.js` | داده‌های نمونه آغازین |
| `src/ui.js` | پوسته، فرم‌ساز، جدول، مودال، ورود، جست‌وجوی سراسری |
| `src/pages1-3.js` | صفحات کاری سامانه |
| `src/admin.js` | پنل مدیریت، مجوزها، تنظیمات و رنگ‌بندی، ساعت زنده و اوقات شرعی، حساب کاربری، ویرایش رکوردها |
| `src/boot.js` | راه‌اندازی |

## قواعد پیاده‌شده

- دسترسی بر اساس **جایگاه سازمانی** است، نه شخص؛ با تغییر متصدی، سوابق جایگاه حفظ می‌شود.
- گردش استاندارد درخواست: ثبت ← کد پیگیری ← ارجاع ← بررسی و همکاری میان‌بخشی ← تأیید ← اجرا ← گزارش نهایی ← بایگانی؛ هر مرحله با تاریخ، ساعت، کاربر و شرح.
- همکاری میان‌بخشی فقط همان درخواست را به مدیریت همکار نشان می‌دهد.
- دستور امام: مسئول دفتر گزارش پیشرفت ثبت می‌کند؛ تکمیل نهایی فقط با تأیید امام جماعت.
- پرداخت: تأیید مدیر واحد ← بررسی امور مالی ← تصویب امام (بالاتر از سقف) ← پرداخت با شماره سند؛ ثبت هزینه خارج از این مسیر ممکن نیست.
- رزرو: تأیید با مدیریت متولی فضا و جلوگیری از تداخل با رزروهای تأییدشده.
- خروج، امانت و جابه‌جایی اموال نیازمند تأیید مدیر واحد مالک یا مدیر داخلی.
- نامه «سری» فقط برای مدیر واحد و امام؛ «محرمانه» برای غیر کارشناسان؛ پیامک‌ها بدون متن محرمانه.
- رویدادهای سیستمی زنجیره‌ای (هر رکورد با اثر انگشت رکورد قبل) و بدون امکان حذف در رابط کاربری.

## مسیر استقرار سروری

این نسخه داده‌ها را در مرورگر نگه می‌دارد تا بدون سرور قابل بررسی باشد. لایه `Store` تنها نقطه اتصال به داده است و برای استقرار عملیاتی با API زیر جایگزین می‌شود:

- `POST /api/auth/login` — ورود با رمز هش‌شده (Argon2) و نشست سمت سرور
- `GET|POST /api/{letters,orders,tasks,requests,reservations,meetings,assets,movements,tx,payreqs,leaves}` — همان توابع `domain.js` در سرور اجرا شوند تا قواعد دسترسی و گردش کار سمت سرور اعمال شود
- `POST /api/files` — مخزن فایل با کنترل مجوز دانلود
- `GET /api/audit` — فقط خواندنی؛ جدول append-only در پایگاه داده (PostgreSQL) با زمان سرور (UTC، نمایش Asia/Tehran)
- `POST /api/sms/dispatch` — صف پیامک متصل به درگاه پیامکی
- `/api/assets` برای اتصال به سامانه مستقل اموال و انبار مسجد
