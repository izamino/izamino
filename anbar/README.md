# سامانه انبار شباب

سامانه مدیریت انبارهای **مجتمع مسجد محور شباب — مجموعه تفکر ناب**.
فارسی، راست‌چین، مناسب گوشی؛ برای ثبت تجهیزات، موجودی، ورود و خروج کالا، امانت، انتقال بین انبارها، درخواست‌ها و اطلاع‌رسانی.

## راه‌اندازی

پیش‌نیاز: فقط **Node.js نسخه ۲۲٫۱۳ یا بالاتر**. هیچ بسته دیگری لازم نیست (پایگاه داده SQLite داخل خود Node است).

```bash
cd anbar
npm start
```

در اولین اجرا، حساب «مدیر کل» با نام کاربری `admin` ساخته می‌شود و رمز آن در خروجی نمایش داده می‌شود
(یا با متغیر `ANBAR_ADMIN_PASSWORD` از قبل تعیین کنید). پس از ورود، سامانه تعیین رمز جدید را الزامی می‌کند.

سایت روی `http://localhost:3000` بالا می‌آید (`PORT` برای تغییر درگاه).

| متغیر | کاربرد |
|---|---|
| `PORT` | درگاه سرور (پیش‌فرض ۳۰۰۰) |
| `ANBAR_DATA_DIR` | محل پایگاه داده، تصاویر و پشتیبان‌ها (پیش‌فرض `anbar/data`) |
| `ANBAR_ADMIN_PASSWORD` | رمز اولین مدیر کل |
| `ANBAR_SECURE_COOKIE=1` | وقتی سایت پشت HTTPS است حتماً فعال شود |
| `ANBAR_BACKUP_KEEP` | تعداد نسخه‌های پشتیبان نگه‌داشته‌شده (پیش‌فرض ۳۰) |
| `BALE_BOT_TOKEN` / `TELEGRAM_BOT_TOKEN` | ارسال اعلان‌های مهم به ربات بله یا تلگرام (شناسه گفت‌وگوی هر کاربر در «حساب من») |
| `KAVENEGAR_API_KEY`, `KAVENEGAR_SENDER` | ارسال پیامک از طریق کاوه‌نگار (شماره همراه هر کاربر) |

برای استفاده روی اینترنت، سرور را پشت یک وب‌سرور با HTTPS (مثلاً Nginx یا Caddy) قرار دهید و `ANBAR_SECURE_COOKIE=1` را تنظیم کنید.

### دستورهای کمکی

```bash
npm run reset-password -- admin NewPass123   # بازیابی رمز در صورت فراموشی
npm run backup                                # پشتیبان‌گیری دستی
npm test                                      # آزمون‌های خودکار
```

## نقش‌ها

| نقش | مشاهده | ثبت و تغییر |
|---|---|---|
| کاربر عادی | همه انبارها | ندارد (فقط ثبت درخواست) |
| مدیر انبار | همه انبارها | فقط انبار(های) تحت مسئولیت خودش |
| مدیر کل | همه انبارها | همه انبارها + مدیریت کاربران، انبارها و پشتیبان‌ها |

ثبت‌نام عمومی وجود ندارد؛ حساب‌ها را مدیر کل می‌سازد. یک نفر می‌تواند مدیر چند انبار باشد.

## قواعد کلیدی

- هر تغییر موجودی فقط با یک «عملیات» (ورود، خروج، امانت، بازگشت، انتقال، اصلاح) انجام می‌شود و با نام ثبت‌کننده در سابقه می‌ماند.
- خروج بیشتر از موجودی قابل‌استفاده پذیرفته نمی‌شود. مقدار اعشاری (مثل ۱۲٫۵ متر) مجاز است.
- هیچ سابقه‌ای حذف نمی‌شود؛ اشتباه با «اصلاح موجودی» و علت الزامی تصحیح می‌شود. کالاها به‌جای حذف، بایگانی می‌شوند.
- موجودی «در انبار»، «در امانت» و «در حال انتقال» جدا نمایش داده می‌شود؛ بازگشت جزئی امانت ممکن است.
- انتقال تا تأیید مدیر انبار مقصد در وضعیت «در حال انتقال» است؛ رد یا لغو، کالا را به مبدأ برمی‌گرداند.
- برای اقلام تاریخ‌دار (داروخانه، آشپزخانه) موجودی هر سری با تاریخ انقضا جدا ثبت می‌شود و در خروج، سری زودتر منقضی‌شونده پیشنهاد و برداشته می‌شود.
- ثبت درخواست موجودی را تغییر نمی‌دهد؛ کاهش موجودی هنگام تحویل واقعی ثبت می‌شود.
- هر روز یک نسخه پشتیبان خودکار در `data/backups` ساخته می‌شود و مدیر کل می‌تواند آن را دانلود کند.

## ساختار

```
server/   سرور بدون وابستگی (http + node:sqlite)
  db.js        جدول‌ها و انبارهای پیش‌فرض
  stock.js     همه عملیات موجودی (ورود، خروج، امانت، انتقال، اصلاح)
  routes.js    API
  notify.js    اعلان‌ها، یادآوری امانت و انقضا، پیامک/پیام‌رسان
  xlsx.js      خروجی اکسل
public/   رابط کاربری (HTML/CSS/JS ساده، فونت وزیرمتن محلی)
test/     آزمون‌های سرتاسری API
```

فونت وزیرمتن تحت مجوز SIL Open Font License در `public/fonts` قرار دارد.
